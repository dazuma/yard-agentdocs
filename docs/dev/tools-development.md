# Command-line tools development

The command line tools use the [Toys](https://github.com/dazuma/toys) framework
and include user-facing tools for building and managing a set of documentation
using the output format implemented in this repo, for quickly looking up items
in documentation, and for installing and managing the agent skills provided.

The command line tools are located in the `toys/` directory, included in the
gem. They are designed to be invoked by most users via
`toys do --gem=yard-agentdocs <tool> <args>` which loads the tools from an
installed `yard-agentdocs` gem. This project itself loads the tools inside its
own namespace so you can simply `toys <tool> <args>` from within the project
directory.

## Tool list

`agentdocs build` documents a single project or gem into a specified output
directory.

`agentdocs gems` documents installed gems into the standard directory structure
`<XDG data home>/yard-agentdocs/gems/<name>-<version>`.

`agentdocs gems clean` removes documentation bundles generated by
`agentdocs gems`.

`agentdocs install-skill` installs the agent skill.

`agentdocs lookup` answers a specific API lookup — for a class, module, method,
or constant — in a documentation bundle.

`agentdocs path` prints a documentation bundle's directory which can be used as
part of a path to grep.

## Tool architecture

Each tool is implemented by a Toys tool file under the `toys/` directory. The
tool file itself uses the DSL to define the tool's interface (e.g. command line
arguments and documentation) but the bulk of the implementation is delegated to
a class under `lib/` so it can be unit tested easily via tests under `test/`.
Detailed design information about a tool is recorded in the class that
implements it.
